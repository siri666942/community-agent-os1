## 一、成本总览(40+ 小时实际运行)

| 成本项 | 实测数据 | 费用 |
|---|---|---|
| Token 消耗 | **in 87,416 / out 63,234**(77 次调用) | 见 §二,月度量级 **< ¥5** |
| 模型调用 | MiMo API(Anthropic 兼容端点) | 同上 |
| Agent 纯运行时长 | 4,429 秒 ≈ **74 分钟** | 计入 API 费用,无额外算力费 |
| 基础设施 | 本机/单云主机 + SQLite(现)→ MySQL(生产) | ≈ **¥100 / 月** |
| 人工闸门时间 | 16 次闸门动作 × 约 3 分钟 ≈ **48 分钟/日**(老板) | 计入人力,非现金支出 |
| 其他 | 知识库维护、素材摄取 | 一次性人工,≈ 2 小时/客户 |

> **一句话结论**:一天全量经营(10 张工单 + 运营包 + 分层 + 首单成交 + 周报)的全部模型成本,买不了一杯咖啡。

## 三、模型调用费用

**计算口径**:费用 = tokens × MiMo API 牌价。以下按示例单价测算(以官方牌价为准):

| 项目 | 数量 | 示例单价 | 费用 |
|---|---|---|---|
| 输入 | 87,416 | ¥1.0 / 百万 tokens | ¥0.087 |
| 输出 | 63,234 | ¥4.0 / 百万 tokens | ¥0.253 |
| **40+ 小时合计** | — | — | **≈ ¥0.34** |
| **月度推算**(每日全量经营 × 30) | — | — | **≈ ¥10** |

**敏感性**:即使单价上浮 10 倍,月模型成本仍 < ¥100;上浮 100 倍也 < ¥1,000——**模型成本永远不是这门生意的成本大头**,大头是人工闸门时间(而它随自动化比例持续下降)。

**人工不可省的部分**:9 道闸门上的拍板(48 分钟/日)+ 知识库维护(≈2 小时/客户一次性)。这不是成本劣势,而是设计特性——资金/对外/承诺事项必须有人负责。

## 五、单位经济模型(以标准版计)

```
收入:¥9,800 / 月(3–5 个社群,500–2,000 家长)
成本:模型 ≈ ¥10 + 基础设施 ≈ ¥100 + 老板闸门时间 24 小时/月(机会成本另计)
毛利:≈ ¥9,690 / 月(毛利率 > 98%,现金口径)
```

对比毛利率常识:SaaS 行业 70–85% 已属优秀——本方案的成本结构里**没有随服务量线性增长的人力**,规模即毛利。

## 六、Xiaomi MiMo 的成本优势

1. **便宜到可以全量质检**:每条应答都过独立合规审核 + 评审循环修复,传统按调用计费的顾虑在这里不成立——实测质检+修复占 46% 调用,月成本仍是两位数
2. **轻量调用形态**:平均单次 1,135 in / 821 out tokens,没有长思维链开销,适合"高频短任务"的 Agent 组织
3. **Anthropic 兼容端点**:一次封装(`opc/llm.py`)全组织复用,77 次调用零适配成本,迁移与扩展无锁定

## 七、商业化推演

| 阶段 | 客户数 | 月收入 | 月现金成本 | 备注 |
|---|---|---|---|---|
| 首单验证(已发生) | 1 | ¥9,800 | < ¥200 | 适趣AI中文·标准版,全链路留痕 |
| 小规模(3 个月) | 5 | ≈ ¥49,000 | < ¥1,000 | 同一 Agent 组织复用,知识库按客户隔离 |
| 规模化(12 个月) | 30 | ≈ ¥294,000 | < ¥5,000 | 阶梯定价 + 旗舰版定制 |

**结论**:这是一门"Agent 边际成本趋近于零"的服务生意——MiMo 把质量内环(质检/修复/审核)的成本降到可以忽略,使"全量合规 + 7×24 + 数据分层"三重能力以低于一名专员的价格交付,而人工只保留不可委托的决策权。
